# VID-019 — календарний перегляд розкладу

Запит: «тут покращи . Можливо використай якиїсь плагін типу красивого прогресивного календаря». На скриншотах — публічний розклад: велика форма дати, порожній стан та довгі табличні рядки. Тип: фіча / покращення UX. Межі — спільний публічний і приватний перегляд, без змін створення занять чи правил доступу.

## Візуальне рішення

- Теза: компактний академічний календар на білому тлі, теплі тонкі межі, бірюзовий вибраний день; незмінний бренд.
- Структура: короткий заголовок → місячний календар і навігація дат → розклад обраного дня, згрупований за парами. На вузькому екрані — одна колонка; без повторення дати в кожному занятті.
- Взаємодія: вибір дня одразу оновлює URL і розклад; «Сьогодні» та попередній/наступний день; pending замість фіктивних відсотків; швидкий hover/focus без декоративної анімації, reduced motion.

## Компонент і межі

React DayPicker `@daypicker/react` 10.0.1: окремий компонент для календарної сітки й клавіатурної навігації. У репозиторії календаря немає; додаткова залежність потрібна, щоб не писати власну доступну сітку. Наявні Base UI та стиль shadcn не переініціалізовуються. [Документація стилів](https://daypicker.dev/docs/styling), типи встановленої версії — джерело точного контракту.

Вибір дати — лише навігація, не запис. Календар показує дні, а не вигадані позначки зайнятості: повного місячного набору занять не завантажуємо. Чисельник/знаменник залишаються ручним попереднім переглядом для поточного дня; вибір іншої дати й «За календарем» скидають ручний week. Обидва тижні, відпрацювання, відсутня опорна дата та invalid URL працюють за чинним серверним контрактом.

## Критерії й план

1. Український місячний календар, понеділок першим, сьогодні й вибраний день відрізняються; дата не зміщується через часовий пояс браузера.
2. Без кнопки «Показати розклад»: вибір дня відразу запитує дані. Є status/pending; URL, reload, Back/Forward, крайні дати 0001–9999 збережені. Перегляд місяця сам по собі не змінює обрану дату.
3. Компактні групи за номером і часом пари; у кожному занятті назва, тип, викладач, аудиторія, групи й правило тижня. Паралельні заняття не перекривають і не приховують одне одного. Без drag/drop, редагування або автозапису.
4. Позначка відпрацювання й попереднього перегляду видима; для preview дата є орієнтиром. Порожній стан має коротке пояснення і зручну навігацію.
5. Токени, логотип і світла палітра збережені. 44px контроли, клавіатура, українські accessible labels, адаптивність 1440/820/390 без document overflow.

Тести готуємо для публічних меж: date-key/зсув дня/URL, групування занять, наявні календарні правила; інтеграційні й браузерні сценарії запускає окремий QA наприкінці пакета. Особлива регресія — реальний день відпрацювання проти дня його розкладу; відсутність дублювання запитів для цілого місяця; pending при повільному переході та повернення після помилки. Попередні зміни native color picker VID-011 зберігаються без перезапису.

## Реалізація

- `components/schedule-calendar.tsx`: клієнтська місячна сітка й переміщення між днями через router; onSelect одразу переходить до date URL. Підписи й клавіатура — DayPicker/uk. Клієнт отримує тільки date/today/path і вже сформований серверний вміст.
- `components/schedule-agenda.tsx`: серверне групування всіх занять пари, паралельні заняття окремими рядками; метадані не втрачаються.
- `components/schedule-view.tsx`: стару GET-форму й велику таблицю замінено календарним workspace; та сама `listScheduleForDate`, без нових SQL чи міграцій. Позначення відпрацювання і preview збережені, є явне повернення «За календарем».
- `lib/schedule-calendar/presentation.ts`: date-only UTC-перетворення, межі років, URLs та групування; бізнес-логіка календаря не перенесена до браузера.
- CSS Module: фірмові токени, 44px клітинки й кнопки, дві колонки на desktop / одна на вузьких екранах, окремий scroll календаря лише коли viewport менший за 7×44px. Рух обмежено pending і hover, reduced motion вимикає його.
- Підготовлено `presentation.test.ts`: межі місяця/року, високосна дата, DST-дні, 0001/0099/9999, скидання ручного week у URL, паралельні заняття, сортування без мутації та empty state.

Статичний огляд за `vercel:react-best-practices`: дані лишаються на сервері; мінімальні серіалізовані props; тимчасовий місяць скидається при зміні committed date без effect; Today повертає календар на правильний місяць навіть коли URL дати не змінився. Додаткові browser-сценарії: browse month B → select B → Back A; Today після browsing іншого місяця; повторний вибір дати з preview; помилка/переривання навігації. Це не фактичний тестовий прогін.

Встановлено лише `@daypicker/react` 10.0.1 і його `react-day-picker` 10.0.1; наявні date-fns / timezone-залежності повторно використано. `pnpm install --ignore-scripts` синхронізував lockfile без запуску lifecycle scripts. Native color picker VID-011 та міграція 012 лишилися незмінними.

Статус: **Реалізовано; QA очікується, NOT_RUN**. Без тестів / build / browser / міграцій / push / deployment на етапі реалізації. Скриншотів і фактичних browser-вимірювань цього варіанта ще немає. Перевірка TDD-меж погоджена постійним дозволом; виконаний red→green цикл не заявляється.
