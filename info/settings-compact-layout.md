# VID-010 — компактні налаштування адміністратора

## Межі та задум

Запит стосується лише масштабу й відступів `/dashboard/settings`. Бізнес-правила, серверні дії, права, дані, логотип, глобальна типографіка та публічні сторінки не змінюються.

Візуальна теза: компактний академічний робочий простір із теплим фоном, білими панелями, читабельною темною типографікою та чинним бірюзовим акцентом.

План контенту: короткий заголовок сторінки → чергування тижнів → календар відпрацювань як одна таблиця → завершення семестру з видимим попередженням → пояснення доступу. У календарі спочатку компактний рядок додавання, потім збережені дати з редагуванням у рядку; пояснення й захист зберігаються.

Взаємодія: зберегти чинні hover / focus та pending-стани. Нових анімацій, приховування важливого тексту або змін масштабу всієї сторінки через `zoom` / `transform` не додавати.

## План реалізації

1. Додати локальний CSS Module до сторінки налаштувань; повторно використати наявні компоненти й дизайн-токени.
2. Зменшити заголовок до 24–32 px, заголовки форм до 18 px, пояснення до 14 px. Зберегти поля не менше 44 px і мобільний розмір тексту полів 16 px.
3. Уніфікувати вертикальний ритм: проміжки 16 px, padding панелей 20 px / 16 px, без суми margin і gap. Відключити розтягування кнопок у grid-рядках.
4. За уточненням «тут можеш зробити як таблицю» замінити картки календаря семантичною таблицею з колонками дати, дня розкладу, типу тижня й дій. Зберегти серверні дії; прив'язати зовнішні поля рядка до його форми через `form` і стабільний `useId`, без вкладених форм або `<form>` між `<table>` та `<tr>`.
5. Статично переглянути diff; позначити «Реалізовано; QA очікується». Передати браузерні вимірювання окремому QA-агенту лише за запитом на перевірку або перед дозволеним релізом.

## Межі перевірок для фінального QA

Це зміна представлення без нової доменної поведінки. Тестова межа — існуючі серверні дії та реальні DOM-форми; після табличного уточнення окремо перевірити правильне включення зовнішніх полів до `FormData` потрібного рядка. Не створювати тести на текст CSS. Red → green цикл у цій задачі не заявляється.

- Viewport 1440, 820 і 390 px; sidebar відкритий / згорнутий, довгі описи, кілька дат відпрацювань, порожній список і дата з журналом.
- Зафіксувати через `ui-spacing-review` розміри заголовків, padding / gap, висоту кнопок та полів; кнопка не розтягується через довгий текст поруч.
- На 390 px звичайні форми в одну колонку, календар зберігає колонки й прокручується лише всередині доступного з клавіатури контейнера. Колонки й дії не стискаються до нечитабельних розмірів; є текстова підказка прокрутки. Документ без горизонтального overflow. Перевірити також масштаб браузера 200% без втрати тексту й дій.
- Tab / Shift+Tab, видимий фокус, читабельні pending / success / error; повідомлення в межах панелей. Немає нових console errors / warnings.
- В ізольованому QA-середовищі: дата чисельника й preview, додавання / редагування / скасування видалення відпрацювання, захищений запис; для завершення семестру перевірити скасування підтвердження без очищення даних.
- Два збережених рядки з різними днем і тижнем: відредагувати один та переконатися, що надіслано лише його поля й актуальну version; інший рядок і незаповнена форма додавання не блокують збереження. Повідомлення success / error належать конкретному запису; захищені дати не можна змінити або видалити.
- У новій розмітці шукати дату через `row` із назвою «Відпрацювання ДД.ММ.РРРР», не через колишній `article`; поля мають доступні назви з датою. Перевірити значення `input.form` / `select.form` та `FormData` конкретної форми; додавання, редагування й видалення не ділять form owner. Після server revalidation у рядку актуальні version і значення.
- Перехід із налаштувань до іншої сторінки не переносить компактні стилі на інші форми. Палітра й бренд не змінені.
- Один фінальний пакет: `pnpm exec tsc --noEmit`, `pnpm test`, `pnpm build` та релевантні наявні ізольовані сценарії за рішенням QA.

## Стан

Реалізовано; QA очікується. Календар у `makeup-days-manager.tsx` має одну семантичну таблицю з колонками «Дата відпрацювання», «За розкладом дня», «Тип тижня», «Дії». Новий запис додається в першому рядку; кожна збережена дата має власні `useActionState`, form owner, version і рядок повідомлень. Дати з журналом показують захист і недоступні дії; підтвердження видалення збережене.

У `settings.module.css`: теплий заголовок таблиці, білі рядки, padding комірок 12 px, контроли від 44 px. Мінімальна ширина таблиці 760 px; локальна горизонтальна прокрутка й підказка з'являються за недостатньої ширини. Контейнер доступний із клавіатури та має видимий focus; кнопка видалення — 44 × 44 px із контекстним `aria-label`. Це задані стилі та розмітка, ще не браузерні вимірювання. Стилі обмежені сторінкою налаштувань; серверні дії, дані, права, палітра й логотип не змінені.

Поточний незалежний QA: **BLOCKED** лише через недоступну перевірку реального масштабу 200%; [QA-20260828-02](qa/reports/QA-20260828-02.md). Функціональні сценарії, захищена дата, tsc / unit / build та браузерні 1440 / 820 / 390 пройшли. Знайдений QA-02-01 (sr-only overflow) виправлено `position: relative` у контейнері таблиці та повторно перевірено; документ більше не переповнюється. Фактичні padding / розміри / focus наведено у звіті. Push і deployment не виконувалися та прямо заборонені користувачем уточненням «не деплой».
