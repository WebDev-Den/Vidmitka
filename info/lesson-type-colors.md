# VID-024 — кольори типів занять

## Поведінка та межі

Адміністратор задає колір типу заняття через нативний picker у компактній таблиці. Назва й колір зберігаються разом явною кнопкою; деактивація не видаляє значення. Приймається лише непрозорий `#RRGGBB`, нормалізований у верхній регістр. Нові типи з швидкого додавання у формі заняття отримують типовий бірюзовий; перейменування через стару межу без поля кольору зберігає поточний колір.

Колір типу не залежить від кольору номера пари на часовій шкалі. Застосовується малим фоновим тегом із видимою назвою та автоматичним контрастним текстом; весь рядок, основна палітра й логотип не перефарбовуються. Спільна позначка використовується у публічному / приватному денному розкладі, найближчих заняттях, «Моїх заняттях» і вибраному занятті журналу. Нативні option лишаються текстовими для переносимості та доступності.

Колір читається з довідника, тому зміна поширюється на наявні заняття без копіювання значення в кожне заняття. Типи без зв’язку показуються нейтрально. У журналу назва збережена історичним знімком: для нього колір знаходиться за збереженою назвою; якщо такого типу більше немає після перейменування, тег нейтральний. Історичні назви та відвідування не переписуються. Деактивований, але не перейменований тип зберігає відображення кольору.

## Дані та реалізація

Міграція `013_lesson_type_colors.sql`: `lesson_types.color`, NOT NULL, default `#0F766E`, CHECK шестизначного HEX. Початкові значення для наявних записів: лекція — `#0F766E`, практична — `#16835B`, лабораторна — `#073C40`, інші — `#0F766E`. Повторне застосування не скидає кольори. Міграція лише підготовлена; робоча БД не змінюється в цьому запиті. До дозволеного релізу потрібне окреме застосування ще не виконаних 012 → 013.

Спільні правила HEX / контрасту й нативний color field використовуються також чинним редактором кольору пари. Серверні actions залишають перевірку схваленого адміністратора; read-моделі передають `lessonTypeColor`. Збереження інвалідує чинні сторінки розкладу, типів, найближчих занять і журналу. Залежності та lockfile не змінюються.

## План і тестові межі

1. Валідація / контраст і міграція; перевірки заплановані через публічні функції та ізольовану БД.

3. Відображення: один компонент тега, дані з усіх чинних read-моделей; жодного довільного CSS із вхідного значення.
4. Фінальний QA всього пакета окремим агентом; зараз тільки підготовка коду й сценаріїв.

Межі TDD погоджені постійним дозволом: правила кольору; save/list типів та захищені actions; read-моделі розкладу, upcoming, my lessons і журналу; міграція / повторне застосування в ізольованій схемі. Тести не запускаються в цьому запиті, red → green не заявляється.
