## Архітектура й тестові межі

За `codebase-design` читання найближчих занять приховує календар, час і порядок за одним інтерфейсом `listUpcomingLessons(now)`. Довідник має окремий модуль, UI не визначає права й не створює тип через довільний текст форми заняття. Ідентифікатор типу зберігається в регулярному занятті; його назва у збереженому журналі — історичний знімок.

Вибірка не обмежена довільно лише сьогоднішнім днем або наступним тижнем. Кандидати охоплюють п’ять 14-денних циклів із додатковим циклом за кожну можливу календарну підміну; кожна підміна здатна прибрати не більше одного проведення конкретного регулярного запису. Окремо додаються всі майбутні явні відпрацювання, зокрема далекі дати без опорного чисельника. Після фільтрації завершених занять застосовуються спільний порядок і ліміт 5.

Головна читає дані на запит, не фіксує час під час build. Картка завантажується окремо зі станами завантаження, помилки й порожнього розкладу; інша частина головної не залежить від успіху цього запиту. Довготривала відкрита сторінка сама не опитує сервер: для актуалізації слід оновити/повторно відкрити сторінку. Після створення/імпорту, зміни типу, календаря чи часу пари відповідні сторінки інвалідуються.

За `tdd` та постійним дозволом у `AGENTS.md` тестові seams погоджені без повторного запиту:

1. Адміністраторські дії довідника → видимий перелік, нормалізація, дублікати, відмова гостю/викладачу.
2. Створення/імпорт заняття → прочитаний тип; невідомий/неактивний тип не створює заняття, старий формат сумісний.
3. `listUpcomingLessons(now)` → реальні найближчі проведення з часовими межами, кількістю, чергуванням, відпрацюваннями та стабільним порядком.
4. Запис журналу → незмінна назва типу після перейменування довідника й завершення семестру.

Тести підготовлено без прогонів. Фінальний QA виконує окремий агент за запитом або перед дозволеним релізом, лише в ізольованій схемі. UI-перевірка — `ui-spacing-review`, без редизайну.

Підготовлені файли: `lib/lesson-types/rules.test.ts`, доповнення тестів форми/парсера/навігації/контракту серверних дій, `info/testing/upcoming-lessons.integration.test.ts`. Ізольований сценарій викликає реальні репозиторії й серверні дії; підміняються лише зовнішні Next.js-адаптери. Параметр `now` дає точні перевірки київської півночі, моменту завершення пари, наступного дня, двотижневого повторення й далеких відпрацювань. Суміжні тести груп/адміністраторів адаптовано до обов’язкового типу нової форми.

Для майбутнього QA (зараз не виконувалося):

```powershell
node --env-file=.env.local info/testing/attendance-runner.mjs --upcoming
```

Harness застосовує 009 і 010 тільки в порожній ізольованій схемі. Параметри `--browser` / `--production` доступні для подальшого браузерного сценарію; наприкінці тесту лишається фіктивне заняття у вівторок-чисельник. Штатне завершення — `stop` та Enter. QA також має прогнати регресії календаря, журналу, груп і ролей, оскільки вони використовують розширені записи занять.
