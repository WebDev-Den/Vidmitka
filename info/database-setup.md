# Підключення бази даних

## Поточний стан

- Постачальник: Neon Postgres через Vercel Marketplace.
- Ресурс: `vidmitka-db`.
- План: `Free` (`free_v3`).
- Регіон: Frankfurt (`fra1`).
- Vercel project: `vidmitka` у команді `webdevdens-projects`.
- Середовища: Production, Preview та Development.

Vercel зберігає облікові дані в зашифрованих environment variables. Секретні значення не повинні потрапляти до Git, документації, CI-логів або клієнтського JavaScript.

## Файли середовища

- `.env.example` — безпечний шаблон, який потрібно зберігати в Git.
- `.env.local` — локальні секрети, автоматично завантажені з Vercel та виключені з Git.
- `.env.production.local` — production-конфігурація для локальної production-збірки та отримання коду першої реєстрації адміністратора; також виключена з Git.

Для оновлення локальних змінних після змін у Vercel:

```powershell
vercel env pull .env.local --environment=development --yes
```

Команда повністю перезаписує `.env.local`. Власні локальні налаштування, які не керуються Vercel, слід зберігати окремо в `.env.development.local`.

## Локальна перевірка

Перевірити реальне з'єднання з Neon:

```powershell
pnpm db:check
```

Застосувати ще не виконані міграції до локально підключеного середовища:

```powershell
pnpm db:migrate
```

Безпечно перевірити додавання студента, захист від дублювання та завершення семестру на тимчасових тестових записах:

```powershell
pnpm db:verify-semester
```

Перевірка не очищає розклад, якщо в ньому є нетестові заняття, і після завершення прибирає лише власні тимчасові записи.

Перевірити пакетний імпорт і захист від конфліктів на тимчасових записах:

```powershell
pnpm db:verify-import
```

Перша міграція `db/migrations/001_class_periods.sql` створює таблицю навчальних пар, захищає унікальність номера та неперетин активних часових слотів і додає початкові 8 пар.

Друга міграція `db/migrations/002_schedule_week_settings.sql` створює єдине налаштування календарного чергування. Поточна форма зберігає будь-яку вибрану адміністратором дату чисельника в `anchor_date` та фіксований тип `numerator` у `anchor_week_type`. Дата читається як календарний текст (`DATE::text`), щоб перетворення в JavaScript Date не зміщувало її через часовий пояс. Попередні налаштування знаменника читаються сумісно; нова міграція не потрібна. Початкове припущення автоматично не встановлюється. Правила й перевірки — у [schedule-weeks.md](schedule-weeks.md).

Третя міграція `db/migrations/003_students_subjects_and_lessons.sql` створює предмети, аудиторії, студентів, предмети викладачів, списки студентів, заняття та журнал завершень семестру. Завершення семестру очищає лише заняття; студенти та їхні предметні зв'язки зберігаються.

Четверта міграція `db/migrations/004_lesson_conflict_guards.sql` додає викладача безпосередньо до заняття та обмеження, які блокують перетин занять одного викладача або однієї аудиторії з урахуванням чисельника, знаменника й обох тижнів.

П’ята міграція `db/migrations/005_local_authentication.sql` створює власні облікові записи й сесії, додає унікальність нормалізованого email, статус схвалення, лічильник невдалих входів і зв’язує навчальні дані з внутрішнім ідентифікатором користувача.

Шоста міграція `db/migrations/006_attendance.sql` додає необов’язкову підгрупу в предметні списки та таблиці журналів і відміток. Вона не видаляє поточні дані. Журнали зберігають знімки списків і занять; видалення розкладу залишає історію.

Сьома міграція `db/migrations/007_student_groups_and_lesson_rosters.sql` переносить наявні назви груп до `student_groups`, пов’язує студентів із довідником та додає окремі списки `lesson_students`. Старі заняття лишаються в режимі `subject`; нова форма створює режим `selected`. Тригер підтримує CSV/JSON із полем `groupName` без зміни формату. Міграцію застосовано 27.08.2026 без видалення робочих даних.

Новий сценарій груп і списків занять перевіряється командою:

```powershell
node --env-file=.env.local info/testing/attendance-runner.mjs --groups
```

Функціональну перевірку імпорту студентів, журналу й завершення семестру запускайте в ізольованій схемі:

```powershell
node --env-file=.env.local info/testing/attendance-runner.mjs
```

Скрипт створює окрему тимчасову роль без права змінювати робочі таблиці, перевіряє міграцію та видаляє тільки власну тестову схему. Параметр `--browser` додатково запускає локальний сервер із тестовим викладачем; штатна зупинка — введіть `stop` та Enter. Звичайний `pnpm test` пропускає цей мережевий тест без спеціальної змінної ізольованого середовища. Допоміжний `info/testing/attendance-cleanup.mjs` без аргументу показує залишки після примусової зупинки, а з точним іменем власної тестової схеми перевіряє тестові облікові записи та видаляє її.

Після успішної перевірки застосунок запускається звичайною командою:

```powershell
pnpm dev
```

Next.js автоматично завантажує `.env.local`. Серверні модулі отримують клієнт бази через `getDb()` з `lib/db.ts`.

## Правила використання

1. Для звичайних запитів застосунку використовується `DATABASE_URL` з пулінгом з'єднань.
2. `DATABASE_URL_UNPOOLED` призначений для майбутніх міграцій та адміністративних операцій.
3. Змінні підключення не мають префікса `NEXT_PUBLIC_` і не передаються у браузер.
4. Нові таблиці створюються лише через контрольовані міграції відповідно до `data-model.md`.
5. Після зміни env-змінних потрібен новий Vercel deployment.
