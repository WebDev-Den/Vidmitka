# Шкала навчального дня — VID-007

Статус: **реалізовано локально; QA очікується (`NOT_RUN`)**. Первинний запит — у [журналі задач](tasks.md). Тести, typecheck, build і браузер не запускалися; нову міграцію не застосовано, публікації не було.

## Поведінка

У публічній верхній частині головної й розкладу показується спільна шкала дзвінків — від початку першої активної пари до кінця останньої. Пари впорядковані за часом, їх номери зберігаються; перерви — фактичні проміжки між слотами. Деактивованих пар немає. Це часовий орієнтир, незалежний від наявності занять, чисельника/знаменника та вибраної дати перегляду розкладу. Напис «Сьогодні · … · Київ» відділяє живий час від перегляду іншої дати.

Маркер не є інтерактивним повзунком: його не можна перетягнути та змінити час. Позиція відповідає секундам поточного київського дня, обмежена краями шкали. Стани: до початку, триває пара, перерва, пари за сіткою завершені. Повні номери й часові межі пар/перерв доступні в розгортаному переліку; вузькі відрізки не втрачають доступного опису.

Кольори обирає адміністратор у чинному розділі «Навчальні пари». Доступна іменована палітра з кольорів затвердженого стилю, без фіолетових акцентів, декоративних градієнтів чи нового primary. Початкові вісім пар отримують різні кольори; повторення дозволене. Кольори впливають лише на шкалу й позначку в довіднику. Історичний журнал не змінюється.

## Тестові межі

Обрані за постійним дозволом на `tdd`; підготовка сценаріїв не означає виконаний red → green цикл.

1. Публічний модуль розрахунку шкали: пропорції пар/перерв, сортування за часом, неактивні слоти, точні межі, порожня сітка, київська північ і літній/зимовий час. Час передається аргументом.
2. Правила пар: дозволені кольори, нормалізація, відхилення недопустимих значень, незмінні перевірки часу/перетинів.
3. Реальні Server Actions + читання довідника в ізольованій БД: лише адміністратор створює/змінює колір; reload повертає збережене; деактивація прибирає пару зі шкали; без доступу до робочих даних.
4. Браузер у фінальному QA: рух часу без reload, перерва та крайові стани, повернення вкладки, збереження кольору, розкривний перелік з клавіатури, відсутність hydration/console помилок і overflow на 1440/820/390 px; перевірка контрасту й reduced motion.

Жодних production-міграцій чи деплою в межах реалізації.

## Реалізовані частини

- `lib/class-periods/colors.ts`: єдина клієнтська/серверна палітра, нормалізація кольору та контрастний текст сегмента.
- `lib/class-periods/rules.ts`, `repository.ts`: обов’язковий валідований колір; чинні перевірки номера/часу/перетинів збережені.
- `/dashboard/periods`: створення й редагування кольору зі зразком; Server Actions перевіряють адміністратора перед записом.
- `lib/class-periods/timeline.ts`: одна функція розраховує позицію, стани, перерви й сегменти для заданих пар і часу; UI не зберігає дубльований стан прогресу.
- `components/public-day-timeline.tsx`: серверне читання актуального довідника, окремий стан помилки, без персональних даних.
- `components/day-timeline.tsx`: початковий серверний timestamp для узгодженої гідратації; локальний годинник щосекунди, без щосекундних запитів до БД. При поверненні до вкладки час перераховується, при демонтажі таймер і слухачі прибираються. Кольори/час довідника оновлюються при наступному відкритті або reload сторінки, не через фоновий live-sync.
- `components/public-header.tsx`: шкала під навігацією на головній та публічному розкладі; завантаження через Suspense.
- `app/globals.css`: лише канонічні кольори/токени; пропорційні сегменти, тонкий маркер, зручний перелік часових меж, адаптивні поля адміністратора. Глобальне reduced-motion правило прибирає плавний рух, не вимикаючи оновлення часу.

Міграція `db/migrations/011_class_period_colors.sql` додає `class_periods.color` з обмеженням палітри. Старі записи без кольору заповнюються за номером (цикл із 8 кольорів); повторний запуск не перезаписує налаштування. Нові SQL-записи мають default бірюзовий; форма адміністратора дає свідомо обрати колір. Часові слоти, заняття та історія журналу не переписуються. Для всього накопиченого коду потрібні **009 → 010 → 011**, лише після дозволеного QA та погодженої міграції робочого середовища.
