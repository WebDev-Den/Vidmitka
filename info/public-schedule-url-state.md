# VID-051 — кореневий публічний розклад і локальний стан перегляду

## Рішення

Канонічна адреса публічного розкладу — `/`. Старий маршрут `/schedule` не видаляється фізично: він робить сумісний redirect на корінь, щоб старі закладки не повертали 404. Параметри `date` і `teacher` більше не є станом перегляду та не з'являються в адресному рядку.

Серверний перший рендер завжди використовує поточну дату `Europe/Kyiv`. Вибраний викладач читається з first-party cookie `vidmitka_public_teacher`; значення застосовується тільки якщо UUID належить чинному активному каталогу викладачів. Це прибирає flash загального розкладу після reload. Вибір «Всі викладачі» видаляє cookie.

## Клієнтська взаємодія

Стрілки, «Сьогодні», вкладки тижня, точна дата й combobox викладача змінюють локальний React-стан і завантажують один день через read-only `/api/public/schedule`. `history.pushState`, `router.push` і GET-навігація для цих контролів не використовуються, тому path/query/hash не змінюються.

Кожен запит має послідовний ID й `AbortController`: новий вибір скасовує попередній, а застаріла відповідь не може перезаписати актуальний день. Під час запиту показується чинний компактний spinner/status; при помилці старий успішний розклад залишається видимим, а користувач отримує повідомлення та кнопку повтору.

Дата навмисно не записується ані в cookie, ані в localStorage. Повний reload, нова вкладка або повторний запуск Electron відкриває сьогоднішній день; викладач лишається обраним.

Виняток — одноразова передача дати з таблиці `/transfers`: звичайний клік записує дату в `sessionStorage`, відкриває `/`, а розклад одразу споживає й видаляє значення. Це не є збереженою датою перегляду: наступне оновлення сторінки знову відкриває сьогодні.

## Фіксований робочий viewport

Візуальна теза: розклад є одним щільним академічним робочим столом на висоту екрана — контекст і керування завжди перед очима, рухається лише великий масив занять.

Контент-план: незмінний верхній header із брендом і контролами → вкладки семи днів → нерухомий заголовок вибраного дня → окремо прокручувана сітка пар. Нових панелей, карток або пояснювального тексту не додається.

Теза взаємодії: єдиний функціональний рух — початкове позиціонування внутрішнього scroll. Для сьогоднішнього дня ціль — активна пара; у перерві — найближча наступна; після останньої — остання пара. Інші дати не прокручуються автоматично. Автопозиціонування виконується один раз для завантаженої дати, тому подальше оновлення годинника не скидає ручний scroll. Коли цільовий рядок виходить із видимої області, з'являється компактна кнопка «До поточної пари»; повернення функціональне й поважає `prefers-reduced-motion`.

На viewport до 680 px заввишки full-height shell вимикається: header і сітка повертаються у звичайний document flow. Це запобігає обрізанню при mobile landscape та типовому desktop zoom 200%; кнопка повернення стає fixed відносно viewport, а цільовий рядок лишається доступним. За ширини до 820 px workspace-header складає бренд і панель керування у два рядки, щоб не створювати горизонтального переповнення на низьких екранах із підвищеним масштабом.

У внутрішньому scroll-контейнері початкова позиція обчислюється відносно самої сітки й задається через `scrollTo`, тому її не змінюють зовнішній header або browser-евристика `scrollIntoView`. Якщо внутрішнього scroll немає через low-height fallback, використовується звичайне позиціонування документа.

## API й валідація

`GET /api/public/schedule` підтримує day-view без обов'язкової групи:

- `date` — необов'язкова валідна календарна дата `YYYY-MM-DD`;
- `groupId` — необов'язковий UUID;
- `teacherId` — необов'язковий UUID;
- невідомий параметр викладача не підмінює серверну перевірку активності в read-model;
- endpoint лишається read-only і використовує чинний cache policy за повним query key.

Week-view зберігає чинний контракт групи; новий UI завантажує тільки day-view.

## TDD і відкладений QA

Погоджені проєктом seams:

1. Pure rules: дата, семиденна навігація, cookie-name/нормалізація UUID, побудова API query і вибір цільової пари для початкового scroll.
2. Route handler: optional group/teacher, явні 400 для невалідних UUID/date, read-model input.
3. Browser: `/`, redirect зі старого `/schedule`, незмінний URL для всіх контролів, cookie persistence, reload → today, fixed header/day heading, внутрішній scroll, кнопка повернення й одноразове позиціонування на поточній/наступній парі, low-height/200% fallback, race/error/pending, keyboard й responsive layout.

Тести готуються разом із реалізацією, але `red → green` не заявляється без фактичного запуску. Запуск — лише наступним незалежним пакетним QA за прямим запитом користувача або перед дозволеним релізом.
