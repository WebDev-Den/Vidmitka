# VID-035 — групи як контекст заняття

## Рішення

Публічна сторінка є загальним розкладом, тому група більше не є глобальним фільтром. Server Component запитує всі заняття вибраного дня або тижня. Наявний `groupId` у repository та public API не видаляється: він залишається сумісною опційною межею для зовнішніх споживачів, але UI його не передає.

## UI-межа

- на всіх ширинах групи показуються постійним компактним рядком унизу картки після викладача;
- рядок груп перебуває у звичайному потоці картки, тому не перекриває предмет, викладача або сусідні заняття;
- довгий перелік груп переноситься в межах картки;
- неінтерактивна картка не отримує focus target або зайвий `tabIndex`;
- запис без груп не отримує порожнього рядка.

Рядок відділений тонкою межею кольору заняття, використовує темний текст і бірюзовий службовий підпис. Tooltip-поверхня, hover-залежність і нова бібліотека не потрібні: контент постійний, неінтерактивний і не керує станом.

## Відкладений QA

Перевірити загальний денний розклад без `group` у URL, паралельні заняття, одну / декілька / жодної групи, Tab/Shift+Tab, touch layout, Back/Forward, 1440/820/390, document overflow та console. Запуск — лише у фінальній пакетній QA-фазі.

## Стан

VID-035 опубліковано раніше. У локальній зміні VID-043 групи читаються з `PublicScheduleItem` і постійно показуються внизу картки; hover/focus overlay та службовий `tabIndex` вилучено. Стан VID-043: **реалізовано; QA очікується**. Production та Git не змінені.
