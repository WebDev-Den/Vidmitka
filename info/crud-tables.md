# VID-012 — компактні таблиці керування

## Напрям і межі

Візуальна теза: компактна академічна таблиця з білими комірками, теплими заголовками, тонкою сіткою й бірюзовими основними діями. Палітра та логотип незмінні.

Контент: заголовок 24–32 px → коротке пояснення → рядок додавання → рядки даних / статусів / дій; повідомлення поруч із відповідним записом. Взаємодія: чинні явні збереження та підтвердження, клавіатурна навігація й focus, без декоративного руху чи автозбереження.

## Інвентаризація

| Розділ | Зміна |
| --- | --- |
| Типи занять | Додавання, назва, стан, збереження / активація в одній таблиці |
| Предмети, аудиторії | Спільний шаблон: назва, стан, додавання / активація; не додавати відсутнє перейменування або видалення |
| Пари та час | Номер, початок, кінець, колір без назви, стан, дії; окрема форма на пару |
| Мої студенти | ПІБ, вибір / створення групи, підгрупа, предмет, додавання й відв'язування в таблиці |
| Викладачі та адміністратори | ПІБ, email, роль, схвалення та чинні дії в таблиці; захищена роль незмінна |
| Мої заняття | Чинна таблиця зі спільною щільністю; тип заняття й його збереження без великої вкладеної форми |
| Створення заняття | Компактна форма основних параметрів; групи й студенти як табличні списки вибору |
| Календар відпрацювань | Збереження реалізації VID-010; включити до QA |
| Імпорт розкладу / студентів | Компактні окремі блоки завантаження з повними лімітами й попередженнями |
| Чисельник, завершення семестру | Уже компактні в VID-010; не приховувати попередження / підтвердження |
| Журнал | Уже табличний, регресія імпорту та відміток; бізнес-логіку не змінювати |
| Вхід / реєстрація | Не CRUD-довідник, поза переробкою |

Уточнення VID-021: [мої заняття та копіювання](lesson-copy.md) — форма типу прихована під native details, додано компактну колонку дій і копіювання з редагуванням чернетки. Новий diff ще не перевірений; історичний PASS VID-012 його не покриває.

## План і спільний module

1. `ManagementTable`: один interface для заголовків, caption, мінімальної ширини й рядків. Implementation централізує семантичну таблицю, сітку, прокрутку та доступний контейнер. Серверні дії не змінюються.
2. `DirectoryManager` використовує два реальні adapters — предмети й аудиторії — з їхніми поточними Server Actions. Не створювати універсальний CRUD-двигун із конфігураціями всіх сутностей.
3. Форми в комірках; зовнішні поля зв'язуються через `form` + `useId`. Межа тестування / seam — фактична форма та чинна дія, не внутрішній CSS або копія серверних правил.
4. Переробити перелічені списки, додати клас компактної робочої сторінки й окремих складних форм. Не переносити стилі на публічні сторінки / auth.
5. Передати весь локальний пакет VID-010–VID-012 незалежному QA після завершення змін; при дефектах виправити пакет і повторити QA.

## QA

Для кожного довідника: додавання, порожній / невалідний запис, reload, доступні зміни стану; декілька рядків не змішують поля. Для типів — перейменування / дублікати; для пар — кольори, час, конфлікти й reset. Для студентів — наявна / нова група, підгрупа, прив'язка до свого предмета та видалення лише зв'язку. Для ролей — pending approval, захищений початковий адміністратор, чинні правила призначення ролі. Для занять — групи, вибір студентів, дані форми, тип у наявному занятті, CSV/JSON workflow. Не змінювати робочі дані; DB лише в ізольованій схемі.

`ui-spacing-review`: 1440 / 820 / 390, фактичний padding комірок, розміри кнопок, довгі назви, таблиці без document-level overflow, Tab / Shift+Tab, popover кольорів, console. Незалежний агент сам визначає достатню матрицю сценаріїв; пропущене не позначається PASS.

Статус VID-012: реалізовано, незалежний QA **PASS** за повторним [QA-20260828-02](qa/reports/QA-20260828-02.md). Спільні компоненти `ManagementTable`, `ManagementFeedback`, `ManagementSubmit` і вузький `DirectoryManager` формують табличний interface; Server Actions і бізнес-правила не змінені. Push і deployment заборонені.

Перший незалежний прогін `QA-20260828-02` завершено: функціональні сценарії пройдено, але зафіксовано P2 `QA-02-01` — absolute sr-only підписи виходили за scroll container на вузьких екранах. Виправлення пакетом: обидва контейнери (спільна таблиця і календар) отримали `position: relative`; підписи та локальний scroll збережені, глобальне приховування overflow не застосовано. Повторний незалежний QA закрив дефект: усі 30 комбінацій сторінка × viewport без document overflow, controls від 44 px. Попередній FAIL зберігається в історії звіту. Весь пакет VID-010–VID-012 залишається BLOCKED лише через недоступну автоматичну перевірку реального масштабу 200% у VID-010; це не новий дефект продукту.
