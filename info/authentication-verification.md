# Перевірка власної автентифікації

Дата: 27 серпня 2026 року.

## Реалізовані сценарії

- реєстрація за ПІБ, email і паролем;
- автоматична роль адміністратора для адреси з `ADMIN_EMAILS` після перевірки `ADMIN_REGISTRATION_TOKEN`;
- новий викладач отримує статус очікування;
- адміністратор схвалює викладача в розділі «Викладачі»;
- вхід за email і паролем;
- завершення серверної сесії під час виходу;
- серверна перевірка сесії, ролі та статусу схвалення;
- блокування облікового запису на 15 хвилин після п’яти невдалих входів.

## Результати функціональної перевірки

| Сценарій | Результат |
| --- | --- |
| Реєстрація нового викладача | Створено обліковий запис, відкрито сторінку очікування |
| Прямий перехід pending-викладача до приватного розділу | Перенаправлено на сторінку очікування |
| Реєстрація адміністратора без коду | Відхилено без створення привілейованого акаунта |
| Реєстрація адміністратора з правильним кодом | Відкрито адміністративний кабінет без ручного схвалення |
| Схвалення викладача адміністратором | Статус збережено, лічильник заявок оновлено |
| Вхід із неправильним паролем | Показано загальну помилку без створення сесії |
| Вхід схваленим викладачем | Відкрито кабінет із меню викладача |
| Прямий перехід викладача до адміністративного розділу | Доступ відхилено, виконано перенаправлення |
| Перехід у приватний розділ після виходу | Перенаправлено на форму входу |
| П’ять невдалих входів, потім правильний пароль | Вхід тимчасово заблоковано на 15 хвилин |
| Browser console після переходу на власну auth-модель | Нових errors немає |

Перевірку виконано через реальні форми у браузері. Створено лише два тимчасові тестові акаунти; після перевірки вони й пов’язані сесії видалені. Реальний обліковий запис власника не створювався.

## Автоматичні перевірки

- `pnpm test` — 26 тестів пройшли.
- `pnpm exec tsc --noEmit` — пройдено.
- `pnpm build` — пройдено.
- `pnpm db:migrate` — міграцію власних акаунтів і сесій застосовано.
- `pnpm db:verify-import` — пакетний імпорт і конфлікти працюють після переходу на внутрішні user ID.
- `pnpm db:verify-semester` — завершення семестру зберігає студентів і їхні предметні зв’язки.

## Обмеження

- Відновлення та зміна пароля — наступний окремий етап.
- Email не підтверджується листом: викладача перевіряє адміністратор, а першу реєстрацію адміністратора захищає серверний код.
- Дизайн та відступи в цій зміні не перевірялися за окремою вказівкою користувача.
