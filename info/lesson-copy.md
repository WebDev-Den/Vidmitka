# VID-021 — компактні заняття й копіювання

## Вимоги та візуальний напрям

Запит і критерії — [tasks.md](tasks.md), VID-021. Візуальна теза `frontend-skill`: щільна академічна таблиця на білій поверхні, теплі тонкі розділювачі, один бірюзовий акцент. Зміст: короткий заголовок і дії створення / імпорту → список із даними → розкривна зміна типу й окремі дії рядка. Це робочий інтерфейс, без hero, декору чи нових зображень. Взаємодії: hover/focus, розкриття лише потрібної форми, pending при збереженні; без декоративної анімації.

## Контракт копії

- Копіювання — заповнення чернетки нового заняття, не негайний запис. Посилання `/dashboard/lessons/new?copy=<id>` тільки читає дані після перевірки схваленого користувача: власник або адміністратор. Викладач може скопіювати призначене йому заняття, навіть якщо його створив адміністратор; права змінювати оригінал не розширюються.
- Параметри й поточний активний склад джерела переносяться у звичайну форму. Неактивні довідники очищаються з поясненням; користувач вибирає активні. Учитель копії — власник джерела, адміністратор може явно вибрати іншого в чинній формі.
- Для `selected` переноситься поточний список джерела; для старого `subject` — поточний список предмета. Нова копія завжди `selected`, без динамічного успадкування майбутніх студентів. Відмітки, історичні заняття, приватні підгрупи іншого викладача не копіюються. Порожній склад дозволено.
- Режим оригіналу не змінюється. Старий `subject` і далі відображає спільний список предмета, зокрема студентів, доданих до цього самого предмета через копію або інші форми. «Оригінал незмінний» означає відсутність записів у параметри джерела чи його історію, а не замороження старого динамічного списку; у формі є пояснення. Окремі `selected`-списки незалежні.
- Користувач змінює будь-які параметри чернетки та явно створює копію. Використовується чинна серверна дія / `createLesson`; конфлікт без зміни слоту не створює дубль і не торкається оригіналу. Скасування — повернення до списку без записів.
- Чернетка не скидається автоматичним reset форми після відповіді сервера: помилку конфлікту можна виправити, не заповнюючи все заново. Після успіху є посилання на список; повторний submit того самого слоту захищений чинними конфліктами.

## План та TDD-межі

1. Серверне читання `getLessonCopySource` із правами в запиті, без окремого mutation API чи міграції.
2. Pure `prepareLessonCopy` готує дозволені defaults для форми; форма й picker приймають початковий вибір. За `vercel:nextjs` сервер передає лише серіалізовані потрібні поля; за `vercel:react-best-practices` ключ форми розрізняє джерела без синхронізувальних effects.
3. Таблиця з меншою кількістю рядків тексту, розкривний тип, колонка дій. Збереження та керування студентами не вилучаються.
4. Підготувати pure-тести defaults і ізольований DB-сценарій: доступ owner/admin/foreign/pending, незмінність джерела, новий ID та пара, незалежний склад, конфлікти, legacy / порожній список й відсутність копіювання відміток. Межі — публічні `getLessonCopySource`, `prepareLessonCopy`, `createLesson`, roster/journal functions; не мокати SQL. Дозвіл користувача на TDD-межі постійний; фактичного red → green до QA немає.

Browser: розкрити/зберегти тип; копія → змінити пару → створити → два записи; незмінений слот → конфлікт із збереженим draft; неактивні довідники; зняти/додати студентів; cancel; keyboard і pending. Регресія звичайного створення та пошуку довідників VID-014, списків VID-015/020. `ui-spacing-review` на 1440/820/390, справжній 200%, overflow, console, focus, довгі назви. Без production-даних і міграцій.

## Реалізація та стан

Реалізовано; QA очікується, `NOT_RUN`.

- `lib/lessons/copy.ts`: одне серверне читання з перевіркою прав і поточним активним складом; без відміток чи mutation.
- `lib/lessons/copy-draft.ts`: явна підготовка defaults і попереджень для недоступних довідників. Довідники завантажуються паралельно на сервері.
- `lessons/new`: підтримка параметра `copy`, keyed форма, початкові значення, скасування та збереження draft після відповіді сервера. Звичайне створення використовує ті самі порожні defaults, що й раніше; запобігання автоматичному reset поширюється на обидва режими.
- `LessonStudentPicker`: необов’язковий початковий вибір; групи обчислюються зі студентів, учасників можна зняти або доповнити. Існуюче додавання студентів до заняття не змінює свого режиму.
- `my-lessons`: локальні стилі щільної таблиці, native details для зміни типу, явні дії копії й студентів із `useLinkStatus`. Кнопки й summary від 44px; прокрутка у спільному контейнері таблиці. Фактичних браузерних вимірювань поки немає.
- Підготовлено `lib/lessons/copy-draft.test.ts` та `info/testing/lesson-copy.integration.test.ts`; новий режим чинного runner — `--copy-lessons`. Звичайний `pnpm test` пропускає DB-сценарій без ізольованого середовища; це не PASS.
- Під час статичного читання harness виправлено індекс пари в не запущеному сценарії VID-020: він має чотири пари, тому використано наявну третю (вільну для цього викладача й аудиторії), а не неіснуючу п’яту. Робочий розклад незмінний.
