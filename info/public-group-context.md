# VID-035 — групи як контекст заняття

## Рішення

Публічна сторінка є загальним розкладом, тому група більше не є глобальним фільтром. Server Component запитує всі заняття вибраного дня або тижня. Наявний `groupId` у repository та public API не видаляється: він залишається сумісною опційною межею для зовнішніх споживачів, але UI його не передає.

## UI-межа

- desktop: повноширинна сітка без лівої панелі; групи з’являються як бічна поверхня картки на `:hover`, `:focus` і `:focus-within`;
- keyboard: картка з групами має focus target і видимий `focus-visible`; текст груп присутній у DOM;
- touch / вузький екран: без hover-залежності, групи показуються постійним компактним рядком;
- запис без груп не отримує порожньої підказки або зайвого `tabIndex`.

Підказка використовує білу поверхню, теплу межу, темний текст і бірюзовий службовий підпис. Нової бібліотеки tooltip не потрібно: контент не інтерактивний, не модальний і не керує станом.

## Відкладений QA

Перевірити загальний денний і тижневий розклад без `group` у URL, паралельні заняття, одну / декілька / жодної групи, mouse hover, Tab/Shift+Tab, touch layout, Back/Forward, 1440/820/390, document overflow та console. Запуск — лише у фінальній пакетній QA-фазі.

## Стан

**Реалізовано; QA очікується.** Server Component більше не завантажує каталог груп для UI та передає `groupId: null`; незалежні запити пар і розкладу виконуються паралельно. З client bundle прибрані пошук, selected state, список посилань і mobile details. Групи читаються з `PublicScheduleItem` і показуються на самій картці. Production та Git не змінені.
