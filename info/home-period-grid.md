# VID-026 — головна сітка розкладу за парами

## Результат і межі

Публічна головна сторінка стає робочим денним табло. Горизонтальна вісь відображає активні номери пар, не дні тижня. Кожна колонка зберігає всі паралельні заняття свого слота та показує порожній стан, якщо занять немає. Повна сторінка `/schedule` і правила вибірки не змінюються.

## Візуальна теза

Щільна академічна сітка на теплому паперовому фоні: біла поверхня, тонкі межі, темна типографіка та наявний бірюзовий акцент. Колір номера пари походить із чинного довідника, а колір типу лишається малою семантичною позначкою.

## Контентний план

1. Спільний світлий header і жива шкала пар із маркером поточного часу.
2. Компактна орієнтація: день, дата, тип тижня / відпрацювання та кількість занять.
3. Одна горизонтальна сітка колонок 1…N; у кожній — час і всі предмети з викладачем, аудиторією та групами.
4. Другорядні дії: попередній / наступний день, прихований вибір дати, повернення до сьогодні та повний розклад.

## Взаємодія

- Поточна пара оновлюється на клієнті за тим самим часовим правилом, що й верхня шкала; колонка має видиму позначку «Зараз» і `aria-current="time"`.
- Вибір дати реалізовано нативним `<details>` і GET-формою, тому основна сітка не поступається місцем календарю та працює без JavaScript.
- Hover / focus підсилюють межу, але не змінюють геометрію. При `prefers-reduced-motion` переходи вимикаються.
- На вузьких екранах прокручується лише сітка з `overscroll-behavior-inline: contain`; сторінка не отримує горизонтального overflow.

## Дані й архітектура

- Server Component визначає фактичну дату в `Europe/Kyiv`, паралельно читає активні пари та чинний денний розклад через наявні репозиторії.
- Чиста презентаційна функція будує колонки за довідником пар, тому порожні слоти не зникають, а паралельні заняття не втрачаються.
- Client Component отримує лише серіалізовані масиви й timestamp, обчислює поточний слот без браузерного запиту до БД.
- Некоректний одиничний `date` повертає сьогодні й показує доступне повідомлення; масив значень не обходить валідацію.

## Підготовлені тестові межі

Pure seam `buildPeriodScheduleColumns(periods, lessons)`:

- усі активні пари присутні, навіть якщо не мають занять;
- неактивні пари відсутні;
- паралельні заняття лишаються разом;
- порядок визначається часом і номером, джерельні масиви не мутуються;
- заняття без відповідного активного слота не створює вигадану колонку.

Сценарії запуску відкладено до незалежного пакетного QA: `pnpm exec tsc --noEmit`, `pnpm test`, `pnpm build`; browser 1440 / 820 / 390, document і локальний overflow, клавіатурне `<details>` / date / navigation, today / selected date, before / pair / break / after, parallel / empty / error, console й reduced motion. До QA після TSX/CSS застосувати `ui-spacing-review`.

## Стан реалізації

**Реалізовано; QA очікується, `NOT_RUN`.** Головна використовує серверну вибірку фактичного дня й окремий клієнтський шар тільки для живого визначення поточної пари. Підготовлено pure-тести побудови колонок. Виконано статичний React/Next і diff-огляд; команди тестів, typecheck, build, браузерний QA, commit, push та deployment не запускалися.
