# Vidmitka — розширений довідник агентів

## Мета проєкту

Vidmitka — український вебзастосунок для обліку відвідуваності студентів. Під час розробки зберігайте українську локалізацію, простий інтерфейс і швидкий сценарій проведення переклички.

## Технологічний стек

- Next.js 16 з App Router
- React 19
- TypeScript у строгому режимі
- Tailwind CSS 4
- shadcn/ui та Base UI
- pnpm
- GitLab CI/CD
- Vercel для preview і production deployment

Перед змінами в Next.js перевіряйте актуальні локальні інструкції в `node_modules/next/dist/docs/`.

## Архітектурні правила

- Не накопичуйте сторінки, бізнес-правила, мок-дані та UI в одному файлі.
- Організовуйте код за функціональними областями: журнал, перекличка, курси, звіти, студенти та автентифікація.
- Виносьте доменні типи й правила з React-компонентів.
- Відокремлюйте UI, прикладні сценарії та доступ до даних через чіткі інтерфейси.
- Використовуйте Server Components за замовчуванням; додавайте `'use client'` лише для локальної інтерактивності.
- Уникайте дублювання компонентів і CSS; розширюйте дизайн-систему через варіанти й токени.
- Не приховуйте помилки TypeScript і не використовуйте `ignoreBuildErrors` як постійне рішення.

## Якість і тестування

Для функцій і виправлень використовуйте цикл red → green → refactor:

1. Опишіть перевірювану поведінку через публічний інтерфейс.
2. Додайте тест, який спочатку падає.
3. Реалізуйте мінімальне виправлення.
4. Запустіть повний набір перевірок.
5. Рефакторте лише після зелених тестів.

Мінімальні перевірки перед завершенням задачі:

```powershell
pnpm exec tsc --noEmit
pnpm build
```

Після додавання тестового стеку також запускайте lint, unit/integration та Playwright E2E-тести. Для змін UI перевіряйте сторінку в реальному браузері, консоль, основний user flow і адаптивний вигляд.

## Доступність і UX

- Усі поля форми повинні мати доступну назву.
- Icon-only кнопки повинні мати `aria-label`.
- Модальні вікна повинні підтримувати Escape, focus trap і повернення фокусу.
- Заявлені клавіатурні скорочення мають бути реалізовані та протестовані.
- Стан навігації, фільтрів і вкладок, який потрібно поширювати або відновлювати, зберігайте в URL.
- Поважайте `prefers-reduced-motion` і не вимикайте масштабування сторінки.

## GitLab CI/CD і Vercel

Production deployment дозволений лише після успішного проходження всіх обов'язкових перевірок.

Очікувана послідовність pipeline:

1. Встановлення залежностей через frozen lockfile.
2. TypeScript typecheck.
3. Lint.
4. Unit та integration тести.
5. Production build.
6. Playwright smoke/E2E-тести.
7. Vercel production deployment лише для захищеної гілки `main`.

Vercel deploy job повинен залежати від тестових jobs через `needs`. Використовуйте захищені й masked GitLab variables: `VERCEL_TOKEN`, `VERCEL_ORG_ID` і `VERCEL_PROJECT_ID`. Не записуйте секрети у файли репозиторію або логи pipeline.

Для merge request використовуйте окреме preview-середовище. Preview deployment не повинен отримувати production-секрети або доступ до production-бази даних.

## Definition of Done

Задача завершена, коли:

- реалізована запитана поведінка;
- typecheck, lint, тести та build проходять;
- основний сценарій перевірений у браузері;
- немає нових помилок або warning у консолі;
- UI доступний з клавіатури та адаптивний;
- документація й CI/CD оновлені, якщо змінився процес запуску або deployment;
- у diff немає секретів, випадкових generated-файлів або сторонніх змін.
