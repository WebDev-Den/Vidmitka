# VID-036 / VID-044 / VID-048 — фільтр публічного розкладу за викладачем

## Рішення

У центрі панелі публічного розкладу використовується один компактний пошуковий список: «Всі викладачі» та активні викладачі за абеткою. Початковий стан не обмежує розклад. За VID-051 конкретний вибір зберігається у first-party cookie `vidmitka_public_teacher`, а дані оновлюються через read-only API без зміни URL або browser history.

## Функціональна межа

- Фільтр працює однаково для одного дня та цілого тижня.
- Усі переходи публічного розкладу зберігають вибраного викладача; повний reload відновлює тільки активного викладача з cookie.
- Фільтрація виконується на сервері до формування read-model, а не приховуванням карток у браузері.
- Для базового заняття береться список `schedule_entry_teachers`. Якщо активний виняток містить власних викладачів, саме він є джерелом істини.
- Для перенесених і разових занять застосовується та сама логіка фактичного викладача.
- Неактивного або невідомого викладача не можна залишити активним у UI: сторінка повертається до «Всі викладачі».
- Поле фільтрує каталог під час введення без зміни серверної вибірки, доки користувач не обере точний запис; вибір одразу завантажує серверну вибірку, не змінюючи URL.
- Пошуковий список підтримує мишу, touch, стрілки, Enter та Escape; при відсутності збігів показує «Викладача не знайдено».
- Вибір груп не повертається; групи залишаються контекстом картки за VID-035.

## Візуальна теза

Один нейтральний білий combobox у чинній академічній панелі, без нової картки або нової палітри. Мала іконка пошуку пояснює можливість введення, а стрілка відкриває той самий каталог. На desktop контрол займає вільний центр між датами; на вузьких екранах переходить у повний рядок. Висота — 44 px, межа та focus відповідають чинним полям.

Popup лишається щільним робочим меню: на desktop його ширина обмежена 520 px, висота списку — 252 px із власним scroll, а рядки мають 36 px. Постійно змонтований live-region порожнього стану не створює верхній пустий відступ, доки збігів достатньо; повідомлення отримує padding лише коли справді показується.

## TDD-межі й відкладений QA

Під час фінального пакетного QA:

1. Repository повертає всіх активних викладачів в алфавітному порядку.
2. Фільтр одного викладача повертає його базові, перенесені й разові заняття та не повертає чужі.
3. Заміна викладача у винятку змінює належність заняття до фільтра; порожня заміна використовує базовий список.
4. «Всі викладачі», невідомий UUID і невалідний параметр не приховують загальний розклад у публічному UI.
5. Вкладки дат, стрілки, «Сьогодні» і date form зберігають поточного викладача в локальному стані; reload відновлює його з cookie та повертає дату до сьогодні.
6. Browser QA перевіряє пошук без збігів, вибір мишею та клавіатурою, Escape, незмінний URL/history, cookie persistence, console, loading feedback і overflow на 1440 / 820 / 390 px.

До прямого запиту «перевір» або перед дозволеним релізом QA не запускається.
