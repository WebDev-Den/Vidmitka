# VID-038 — імпортований семестровий розклад

## Виправлений контракт

`teacher-schedule-lessons.json` описує базові заняття семестру, а не незалежні разові події. Для кожного рядка:

- `date` — дата, з якої саме цей запис починає діяти;
- `dayOfWeek` — день повторення;
- `weekType` — чисельник або знаменник;
- дата завершення — `31.12` року з поля `date`, для поточного файла `31.12.2026`;
- `substitution` зберігається лише в санітизованому аудиті джерела й не змінює базову повторюваність.

Цей контракт замінює попереднє припущення в `teacher-schedule-json-mapping.md`, за яким усі рядки були `one_time`-винятками.

## Модулі й сумісність

Parser повертає `validFrom`, `validUntil`, день і тип тижня як готовий доменний запис. Repository ховає транзакційний upsert довідників, `schedule_entries` і junction-таблиць за чинними `previewTeacherScheduleImport` та `commitTeacherScheduleImport`; зовнішня interface імпорту не розширюється.

Для вже наявних `schedule_exceptions` із `source_kind=teacher_schedule_json`:

1. Public resolver до повторного імпорту трактує активні записи як повторювані від `original_date` до кінця відповідного року й не повертає службові change metadata.
2. Повторний import preview класифікує legacy-виняток як update/migration, навіть якщо payload не змінився.
3. Commit створює або оновлює базовий `schedule_entries`, переносить зв’язки та переводить старий виняток у `superseded`.
4. Наступний повтор того самого файла пропускає незмінні базові записи.

Справжній `one_time`, створений адміністратором без такого `source_kind`, залишається винятком і показує «Разове заняття».

- Public schedule: запис не видимий до `validFrom`, видимий на наступному відповідному чисельнику/знаменнику, не видимий після 31.12.2026; календарне перенесення використовує потрібний день/тиждень.
