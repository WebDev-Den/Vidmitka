# VID-023 — публічні перенесення пар

## Межі та план

У верхній навігації головної, розкладу й нової сторінки є «Розклад» та «Перенесення пар». Другий пункт веде на `/transfers`, не на адміністративну форму й не на видалений блок ролей. Перегляд не потребує входу. Адміністратор бачить посилання до чинного календаря в налаштуваннях; редагування залишається захищеним.

План реалізації: публічна проєкція чинного календаря → серверна таблиця / порожній стан → спільна навігація з active / pending та mobile-доступом → оновлення сторінки після адміністративної зміни. Нової сутності, міграції, залежності чи дубліката календаря немає.

Таблиця показує всі активні записи за зростанням дати: дату відпрацювання, день розкладу, тип тижня. Минулі дати не приховуються. За VID-051 посилання рядка запам'ятовує дату одноразово в `sessionStorage` і відкриває canonical `/` без query: кореневий розклад споживає та одразу видаляє значення. Наступний reload знову відкриває сьогоднішній день. Дані автора, версія запису, наявність і вміст журналу не входять до публічного результату.

## Оформлення й поведінка

Збережено спільний header, логотип, шкалу й канонічні токени. Повторно використовується компактна таблиця з локальною прокруткою, коротким заголовком і текстовими позначеннями чисельника / знаменника. Навігація має 44px цілі, `aria-current`, клавіатурний focus та індикатор реального переходу з reduced motion; на вузькому екрані займає другий рядок header. Жодних великих повторних карток чи декоративних анімацій.

Сервер читає календар для запиту; публічна сторінка інвалідується після успішного додавання, редагування або видалення в адміністратора. Порожня таблиця означає відсутність активних перенесень, а не помилку БД. У разі помилки показується окреме повідомлення без технічних деталей; у процесі читання — стан завантаження.

## Межі TDD та фінальний QA

Постійний дозвіл на вибір меж уже наданий у `AGENTS.md`. Межі: публічне читання календаря `listPublicMakeupDays`, чинні адміністративні save/delete actions і браузерні переходи `/` → `/transfers` → `/` з одноразовою датою без URL-параметрів. Для БД розширюється ізольований сценарій `info/testing/makeup-days.integration.test.ts`, без доступу до робочих даних. Запуск відкладено; red → green не заявляється.

Сценарії наступного пакета:

- Гість, викладач, pending-акаунт та адміністратор можуть відкрити `/transfers`; кнопка керування лише у схваленого адміністратора. Мутації гостя / викладача / pending як і раніше відхиляються.
- Порожня вибірка; після створення видно тільки `date`, `dayOfWeek`, `weekType`; редагування змінює день і тиждень; деактивація прибирає запис.
- Кілька дат, доданих не в хронологічному порядку, відображаються за датою; захищений журналом запис доступний для публічного перегляду без даних журналу.
- Після успішних save/delete інвалідується `/transfers`; повторний перехід показує актуальний список.
- Посилання дати показує саме відпрацювання, не звичайний день тижня і не preview; «обидва тижні» в розкладі враховуються як раніше.
- Меню доступне на 1440/820/390 px, active / pending працюють; Tab / Enter, Back / Forward, фокус прокрутки таблиці, reduced motion. Немає document-level overflow, нових console errors / warnings; вимірювання через `ui-spacing-review` лише у фінальному QA.
- Повільна / недоступна БД: окремі loading / error стани, без хибного повідомлення про відсутність перенесень. Відсутній `#roles` і блок «Можливості» не повертається.

Статус: реалізовано; QA очікується, `NOT_RUN`. Розширено наявний ізольований DB-сценарій; тести, typecheck, build, браузер, міграції, push та deployment не запускалися. Статичне читання / diff не є результатом QA.
