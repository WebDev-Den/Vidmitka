## Потребує виправлень

1. **QA-11-01 — VID-061 — P1.**
   - Кроки: виконати `pnpm exec tsc --noEmit` або `pnpm build` на перевіреному dirty state.

2. **QA-11-02 — VID-061 — P1.**
   - Кроки: подати server env `QSTASH_URL=https://any-non-qstash-service.upstash.io` з валідними іншими значеннями й викликати status/initialization adapter.
   - Очікувано: неканонічний QStash endpoint відхиляється без мережевого виклику та без передачі bearer token.
   - Фактично: `parseQStashUrl` у `lib/public-push/qstash-schedules.ts:85` перевіряє тільки суфікс `.upstash.io`; цей arbitrary host пройде і одержить `Authorization: Bearer`.
   - Вплив: порушено критерій відхилення arbitrary QStash URL; помилкова/скомпрометована env-конфігурація може розкрити token сторонньому Upstash endpoint. Потрібен строгий allowlist документованих QStash API hostnames і negative unit test.

3. **QA-11-03 — VID-061 — P2.**
   - Кроки: подати `PUSH_SCANNER_URL=https://other.example/api/internal/push/scan` і викликати adapter.
   - Очікувано: тільки canonical production scanner URL приймається.
