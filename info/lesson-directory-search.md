# VID-014 — пошук і швидке додавання довідників

## Реалізаційний план

1. Спільний Base UI Combobox із пошуком у popup для предмета, аудиторії, типу. Пошук / фільтрація локальні; у form payload — тільки ID вибраного активного запису.
2. Явний пункт створення для адміністратора за відсутності точного збігу. Серверна дія перевіряє роль і викликає чинні доменні правила. Репозиторії повертають option через INSERT/UPDATE RETURNING; старі mutation-функції зберігають success/message контракт через обгортки.
3. Додавання — окрема дія, не submit основної форми; без вкладених form, автоматичного reset і втрати draft. Локально зберігаються лише нові options; решта надходить із server props.
4. Неактивні записи не створюються повторно й не активуються автоматично; сервер повертає чинне повідомлення дубліката. Викладач має пошук і підказку звернутися до адміністратора.

Обрано наявний Base UI 1.5, без нових залежностей. Skill `vercel:shadcn` використовується для доступного комбінованого поля, його темна палітра за замовчуванням не застосовується: користувацький канон має пріоритет. API звірено з локальними деклараціями та [офіційною документацією Combobox](https://base-ui.com/react/components/combobox). Для Server Actions прочитано локальний Next forms guide.

## Межі наступного QA

- Pure rules: нормалізація пошуку, частковий / точний збіг, валідні / невалідні назви, merge options без дублювання ID.
- Ізольовані integration: створення всіх трьох записів адміністратором повертає реальний ID / нормалізовану назву; дублікати, неактивні дублікати, невалідний kind / name; teacher / pending / anonymous відхиляються; старі room/subject/type mutation-контракти незмінні.
- Browser: порожні й непорожні довідники; вибір / пошук / створення / повторний пошук; невалідний запит; збереження інших полів, груп і студентів при додаванні; у FormData рівно один правильний ID на поле, жодних synthetic create IDs / query. Створення заняття з новими записами, reload.
- UI1440/820/390, popup collision, довгі назви, Tab/стрілки/Enter/Escape, повернення focus, pending, помилки мережі, без нових console помилок і document overflow. Використати `ui-spacing-review` у фінальній QA-фазі.

## Виконано

- `components/private/directory-combobox.tsx` і CSS Module — спільний пошук у popup, доступні підписи, локальна прокрутка, команда додавання, повідомлення. Світлі кольори й токени збережені; логотип не змінювався. Skill `vercel:shadcn` визначив використання наявного доступного Base UI; правила `vercel:react-best-practices` застосовано під час статичного читання змін, без браузерного прогону.
- `lessons/new/use-lesson-directories.ts` — зберігає тільки локально створені options та вибрані ID; `useTransition` / захист повторного кліку; не блокує редагування решти draft, але блокує submit заняття під час створення довідника. Нове значення й серверні props об'єднуються за ID.
- `lessons/new/directory-actions.ts` — async-only серверний модуль, перевірка адміністратора до try/catch, whitelist видів довідників, revalidation. Пошук і вибір для викладача доступні; прихованої можливості створити запис без прав немає.
- Репозиторії subjects / rooms / lesson-types мають option-returning методи з RETURNING; старі методи зберегли точний контракт `{ success, message }`. Схема БД, авторизація та правила створення заняття незмінні.
