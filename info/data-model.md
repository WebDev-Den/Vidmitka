# Концептуальна модель даних

## 1. Призначення документа

Документ фіксує смислову структуру даних системи керування розкладом. Він є основою для подальшого проєктування БД, але не визначає конкретну БД, фізичні типи даних, спосіб зберігання, обміну або реалізації.

## 2. Основні сутності та атрибути

### Викладач

| Атрибут | Призначення |
| --- | --- |
| Ідентифікатор | Однозначно відрізняє викладача |
| Повне ім'я | Відображається в розкладі та адміністративних розділах |
| Дані облікового запису | Дозволяють пов'язати користувача з викладачем |
| Стан | Активний або неактивний |

Правила:

- активний викладач може бути призначений на нове заняття;
- неактивний викладач зберігається в історичних і чинних зв'язках для контролю;
- викладач бачить усі призначені йому заняття, але право редагування й видалення має лише для заняття, де він одночасно є автором створення та призначеним викладачем.

### Навчальний предмет

| Атрибут | Призначення |
| --- | --- |
| Ідентифікатор | Однозначно відрізняє предмет |
| Назва | Назва, яку бачить користувач |
| Стан | Активний або неактивний |

Назва має бути унікальною серед активних предметів. Неактивний предмет не можна вибрати для нового заняття.

### Аудиторія

| Атрибут | Призначення |
| --- | --- |
| Ідентифікатор | Однозначно відрізняє аудиторію |
| Назва або номер | Значення, яке бачить користувач |
| Стан | Активна або неактивна |

Назва або номер мають бути унікальними серед активних аудиторій. Неактивну аудиторію не можна вибрати для нового заняття.

### День тижня

| Атрибут | Призначення |
| --- | --- |
| Значення | Дозволений навчальний день |
| Порядок | Позиція дня у тижневому розкладі |

Перелік днів є впорядкованим. Чи використовуються всі сім днів, визначається правилами навчального закладу.

### Пара

| Атрибут | Призначення |
| --- | --- |
| Ідентифікатор | Однозначно відрізняє пару |
| Номер | Значення, яке вибирається під час створення заняття |
| Порядок | Позиція в межах навчального дня |
| Назва для відображення | Людинозрозуміле позначення |
| Стан | Активна або неактивна |

Номер пари унікальний. Для нового заняття можна вибрати лише активну пару.

### Тип навчального тижня

Допустимі значення:

- чисельник;
- знаменник;
- обидва тижні.

Інших значень не передбачено.

### Навчальний період

| Атрибут | Призначення |
| --- | --- |
| Ідентифікатор | Однозначно відрізняє навчальний період |
| Назва | Людинозрозуміле позначення періоду |
| Початок | Перша календарна межа дії періоду |
| Завершення | Остання календарна межа дії періоду |
| Тип першого тижня | Чисельник або знаменник, від якого починається чергування |
| Стан | Запланований, чинний або завершений |

Період потрібен для визначення типу конкретного тижня та меж актуальності розкладу.

### Заняття

| Атрибут або зв'язок | Обов'язковість | Призначення |
| --- | --- | --- |
| Ідентифікатор | Так | Однозначно відрізняє заняття |
| Викладач | Так | Хто проводить заняття |
| Предмет | Так | Який предмет викладається |
| Аудиторія | Так | Де проходить заняття |
| День тижня | Так | Коли проходить заняття |
| Пара | Так | Яку позицію дня займає заняття |
| Тип тижня | Так | Чисельник, знаменник або обидва тижні |
| Навчальний період | Так | У межах якого періоду діє заняття |
| Автор створення | Так | Хто створив заняття |
| Стан | Так | Чинне або вилучене з чинного розкладу |

Назва предмета не дублюється як самостійний текст заняття: заняття посилається на предмет із керованого переліку.

Автор створення не змінюється під час подальшого редагування. Якщо адміністратор створив заняття для викладача, це заняття є частиною розкладу викладача, але викладач не отримує права змінювати або видаляти його.

## 3. Кардинальності зв'язків

| Зв'язок | Кардинальність | Правило |
| --- | --- | --- |
| Викладач → Заняття | Один до багатьох | Викладач може проводити багато занять; заняття має одного викладача |
| Предмет → Заняття | Один до багатьох | Предмет може входити до багатьох занять; заняття має один предмет |
| Аудиторія → Заняття | Один до багатьох | Аудиторія використовується багатьма заняттями в різні слоти |
| День тижня → Заняття | Один до багатьох | Багато занять можуть припадати на один день |
| Пара → Заняття | Один до багатьох | Одна пара використовується в різні дні та тижні |
| Навчальний період → Заняття | Один до багатьох | Період містить багато занять; заняття належить одному періоду |
| Автор → Заняття | Один до багатьох | Один користувач може створити багато занять |

## 4. Концептуальні обмеження цілісності

### Обов'язковість

Чинне заняття не може існувати без викладача, предмета, аудиторії, дня, пари, типу тижня та навчального періоду.

### Посилальна актуальність

Нові заняття можуть посилатися лише на активного викладача, активний предмет, активну аудиторію та активну пару.

Деактивація елемента не повинна руйнувати значення вже створених занять. Такі заняття позначаються для адміністративного контролю.

### Унікальність довідників

- активні предмети не дублюються за назвою;
- активні аудиторії не дублюються за назвою або номером;
- номери пар не дублюються;
- один викладач не повинен мати кілька активних облікових записів для тієї самої особи.

### Несуперечливість розкладу

Для занять, що мають однаковий день, пару та перетин типів тижня:

- не допускається однакова аудиторія;
- не допускається однаковий викладач.

Ці обмеження діють у межах одного навчального періоду. Якщо періоди перекриваються календарно, правила мають застосовуватися до спільної частини їх дії.

## 5. Похідні представлення

Наведені нижче структури формуються з основних сутностей і не потребують окремої самостійної сутності.

### Загальний розклад

Впорядкований перелік занять за навчальним періодом, типом тижня, днем і парою.

### Власні заняття викладача

Загальний розклад, обмежений конкретним викладачем.

### Зайнятість аудиторії

Заняття, згруповані за аудиторією, днем, парою та типом тижня.

### Зайнятість викладача

Заняття, згруповані за викладачем, днем, парою та типом тижня.

### Проблеми актуальності

Перелік занять із конфліктами або посиланнями на неактивні сутності.

## 6. Життєві цикли

### Викладач, предмет, аудиторія та пара

1. Створено.
2. Активовано й доступно для вибору.
3. Деактивовано й недоступно для нових занять.
4. Може бути остаточно вилучено лише за відсутності пов'язаних занять, які мають зберігати смисл.

### Навчальний період

1. Запланований.
2. Чинний.
3. Завершений.

Одночасне існування кількох чинних періодів потребує явного правила їх взаємодії та не повинно створювати неоднозначність типу тижня.

### Заняття

1. Створюється як намір.
2. Проходить перевірку прав, довідників і конфліктів.
3. Стає чинним у розкладі.
4. Може бути змінено з повною повторною перевіркою.
5. Після видалення перестає входити до чинного розкладу.

## 7. Питання для майбутньої деталізації БД

Після затвердження функціональної моделі окремо потрібно визначити, не змінюючи наведених бізнес-правил:

- правила збереження історії змін;
- потрібний строк зберігання вилучених занять;
- правила остаточного видалення облікових записів і довідників;
- підтримку кількох навчальних періодів;
- необхідність додаткових атрибутів аудиторій і предметів;
- спосіб відображення авторства та часу змін;
- правила перенесення розкладу між навчальними періодами.

Фізична модель даних створюється лише після погодження цих рішень.
